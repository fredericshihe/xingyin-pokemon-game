# 战斗特效与播放时序修复（2026-09-17）

## 范围与根因

本轮只修改战斗展示与播放调度。生产发布使用 `/tmp/pokemon-battle-smooth-release-20260917` 隔离副本，基于上一轮线上 `battle-vfx-20260917-v1`，不包含其他任务的地图 v2/v3、天王难度或尚未生成的背景。

代码链路中确认的问题：

- 角色 CSS 动画、材质 Canvas 和扣血分别计时；命中时会提前清除仍在播放的角色动作。
- 图集加载与解码消耗原本的攻击时间，另一个定时器还会提前销毁特效。
- 强制 hit-stop 产生 30–82ms 的停顿；逐字对白更新让整个战斗场景反复渲染。
- 竖屏按整个视口缩放近身特效，导致压落、冲撞与爪击的材料过小、过淡；部分冲撞技命中前缺少轨迹。
- iPadOS 的桌面 UA 与缺失的 deviceMemory 可能使平板进入桌面高画质档。

## 最终实现

- 图集解码完成后才启动可见动画。角色 Web Animations、Canvas、出手音效与命中回调共享播放生命周期；命中帧绘制后提交伤害与反馈。
- 动画完成后才进入后续流程；取消或准备失败不会凭定时器提交隐藏伤害。长帧最多推进 40ms；标签页隐藏暂停可见时钟。
- 移除强制 hit-stop 与重复清理定时器；轻/中/重/终极攻击分别约 820/1040/1220/1480ms；连击与蓄力保留各自节奏。
- 独立对白组件隔离逐字更新；平板标准档控制像素密度，移除全屏模糊。
- 依据角色尺寸保持特效可读；补强压落冲击环与尘土、冲撞轨迹与碎屑、弧形爪痕、龙焰俯冲与逆鳞连续撕扯。不使用文字、符号、图标充当招式特效。

- 322 个招式全部实绘：非空、像素摘要各异、透明度 >50 的可见面积均达到手机尺寸检查阈值。最低约 185 CSS 像素；标准档最高 64 次绘制/帧，预算 110。

- 最终发布候选：平板 CPU ×3 与手机 CPU ×4，共 22 组动态播放，全部完成；HP 与命中反馈同步，无超过 50ms 的帧间隔，无 Long Task。
