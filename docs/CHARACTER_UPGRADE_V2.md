# 全人物 Blender v2 升级

日期：2026-10-11。用户授权将游戏人物进一步区分，并通过本机 Blender 全面制作、导出和接入升级。

## 实际覆盖

- 现有31个兼容角色模型使用v2作者化脚本精修，逻辑模型键保留。
- 为78位原先复用普通/部下/首领/商人模型的人物增加独立模型，使用稳定的地图与事件绑定。
- 实际地图中的96位NPC现在使用96个独立模型；几何检查排除顶点顺序与颜色缝差异，确认96套不同物理形体。
- 包含主角和兼容基础造型，共109个角色GLB；另有自行车和跑车两套同一主角的载具模型。
- 96个人物的事件名称、原落位坐标和角色绑定与升级前快照一致。战斗、商店、鱼商、首领门控和云端结算仍使用既有事件ID。

身份配置包括年龄、体型、脸宽、发型、头饰、衣装与职业装备。隐居老人、老海盗和三位鱼商分别独立制作；八位地区首领具有各自主题和装备。默认人物模板继续作为兼容和可编辑基础，不重新用于当前96个人物的共用实例。

## 美术与比例

主角保留红帽、红衣、青绿背包；细化衣袖、手掌与手指，减少帽发穿插，并增加衣领/披风/冠饰的实际厚度。NPC增加短发、卷发、辫发、发髻、老人发型与胡须；职业道具采用实体几何连接到服装或携带位置。

主角总高1.55。独立普通人物按年龄为1.48/1.52/1.58，部下1.72，地区首领1.84。道馆部下的最终总高1.73，天王1.94，避免源模型高度与落位缩放叠乘造成明显巨人比例。模型总高不等于写实人体身高；保留地图原地面抬升字段。

材质使用一个共享顶点色材质与每顶点 `_CHAR_SURFACE` 分区数据，区分布料、皮肤、皮革、眼睛与金属。浏览器着色器保留这些分区，不再让全人物的统一粗糙度/金属度覆盖职业细节。这里采用轻量表面分区方案，运行资产不依赖外部贴图。

## 动作与呈现

- 主角使用12个分部件动作节点：身体、头、左右上臂、前臂、大腿、小腿和脚。保留旧版六节点名称，增加父子关节与左右握持插槽。
- 两段腿长求解控制落脚，支撑阶段脚部保持平直；正常游戏中的步频按实际位移调整，在静态图册中支持原地行走演示。
- 根据实际关节的完整腿长和初始角度求解落脚。83个可漫游NPC及主角的支撑脚高度和地面位置通过最终GLB采样；主角支撑膝角小于10度，上半身高度保持稳定。
- 钓鱼优先使用 `rightGrip` 握持插槽，再回退到旧版手臂包围盒，保留地图演出、指针时钟和服务端结果边界。
- 普通NPC按实际位移积累步态相位，单格移动放慢至1400–1800ms；脚踝反向补偿使支撑脚平直，停止时恢复站姿。移除主角按瓦片整体上抬的动作；闲置呼吸不影响连续行走的上半身稳定。
- NPC柔和接触阴影随已有角色控制器移动，保留交互标记和战后视觉状态。
- 步行、骑行、驾驶通过同一个v2人物作者化源重建头脸、衣帽和背包。

本实现采用分部件关节和轻量GPU关节变形，不把这些资产描述为完整蒙皮骨架或面部表情系统。GLB动画仍由既有游戏帧循环驱动。

NPC步态初次增加属性时超过显卡顶点属性上限，导致人物不显示；最终将三个顶点权重合为一个向量、实例摆幅与髋部位移合为一个向量，浏览器真实地图确认无着色器错误。地面枢轴与踝点同模型一起校正，表面及阴影使用同一套关节变形。

对战介绍按保存的模型键或旧记录中的地图事件查找真实NPC，并从同一份GLB生成透明人物图。配件不再影响躯干中心与姓名对齐；模型和文字使用统一纵向布局，入场动画不再叠加旧的百分比位移。传送过场直接使用当前v2主角图，不先显示旧版二维头像。

游玩时长原本单次8秒心跳失败就进入错误页。现在短暂传输故障或空心跳响应会先暂停输入并自动重建服务端会话；开始和读取状态可有限重试。权限拒绝、时间用完及持续不可确认仍保持原暂停规则，未修改数据库或教师时长限制。

## 加载修复与运行预算

预载API传入可选的undefined值时，原默认配置被覆盖，`retries`变为undefined、尝试次数为NaN，产生反复HEAD检查而不GET模型。`resolveModelPreloadOptions`现在只合并有值的覆盖参数，保留默认下载重试配置；人物图册和真实地图回归确认可加载。

全部角色压缩后约4.4MB；每个NPC仍为单网格、单材质。压缩只从干净作者化导出运行，对已有压缩记录跳过，避免重复减面。读取最终文件后记录真实面数、字节和包围盒，并确认法线、颜色、表面属性及关节层级保留。

当前所有地图实际GLB键共544个。GLB运行缓存容量从220增加到640，覆盖独立人物增加后的地图资源集合。新角色使用 `/assets/3d/xingyin-characters-v2/`，与旧精修重定向分离；既有资源保留。

## 可编辑源与重建

完整可编辑工程：`art/characters/v2/xingyin-character-collection.blend`，包含109个人物、最新NPC关节数据和最终主角。另保留主角、NPC、骑行和驾驶独立源工程。

主要命令：

```sh
/Applications/Blender.app/Contents/MacOS/Blender -b --python scripts/blender/build_character_upgrade_v2.py -- --skip-preview
/Applications/Blender.app/Contents/MacOS/Blender -b --python scripts/blender/build_player_bicycle_v2.py
/Applications/Blender.app/Contents/MacOS/Blender -b --python scripts/blender/build_player_sports_car_v2.py
node scripts/optimize-character-upgrade-v2.mjs
npm run generate:map-manifest
node scripts/audit-character-upgrade-v2.mjs
```

主角单独修改使用 `--only player_child_adventurer`；NPC步态使用 `--npc-walk`。部分导出合并角色与载具清单，不丢弃未修改记录。`assemble_character_upgrade_scene.py`把最新NPC和主角的独立工程合回完整源工程，不修改已验证运行GLB。

## 验证和本地审阅

- `audit-character-upgrade-v2.mjs`：109角色、96不同物理形体、实际地图映射、尺寸、预算、表面分区、主角肘膝踝父子关系与握持插槽。
- `audit-character-assets.mjs`：角色注册、原点、法线、颜色、预载和真实文件预算。
- `audit-special-npc-models.mjs`：饲养家与计时员的独立模型、原事件和主角尺度。
- `audit-elite-character-models.mjs`：16道馆人物的独立形体、最终比例和各主题归属。
- `audit-npc-walk-visual.mjs`：12个兼容NPC的步态属性、停止姿态、批次隔离和阴影变形。
- `audit-character-gait.mjs`：全部83个漫游NPC的支撑脚高度与滑移、停止姿态、主角上半身稳定及96个介绍模型映射。
- `audit-playtime-recovery.mjs`：模拟网络超时、有限重试、旧响应隔离、权限拒绝、到期和失效会话恢复，不使用真实账号。
- `audit-map-save-compatibility.mjs`：225个旧版/当前存档落点案例，保留金币、库存和永久进度。
- 钓鱼目录、动作和奖励审计通过；实际地图桌面/手机30例钓鱼演出回归通过。
- 人物图册及14张地图加载/着色器检查通过；另记录主角落脚与握持验证。
- 手机视口与CPU四倍节流采样约59–60FPS、无资产加载失败。首次准备约10秒触发性能WARN；此项与近60FPS的持续渲染分开报告，不作为真机性能保证。

开发态人物图册：`/character-preview`，可查看全部109个角色、前左右后及主角行走，且不调用账户或云存档。正式构建不启用该入口。

截图、资产审计、步态验证和性能报告位于 `output/character-upgrade-v2/`。升级前8个重要源码文件与主角参考图保存在其before子目录，用于对照。
