## 1. 排查目标

本计划用于严格排查游戏内所有与宝可梦成长、战斗、资源、商城、背包、云存档同步相关的链路，目标是确保：

- 正常游玩过程中不会出现进度莫名回退到前一秒或旧状态覆盖新状态。
- 宝可梦升级、进化、学技能、忘技能、经验变化、血量和技能值变化都符合预期。
- 金币、能量、背包物品、老师奖励、战斗奖励能够及时写入后端并能正确读取。
- 所有宝可梦、技能、进化链、道具、地图刷怪、战斗参数有可重复验证的审计脚本或手测用例。
- 在确认功能稳定后，梳理可以提升游戏性和品质的动画与反馈补充点。

排查顺序：

```text
数据表完整性 -> 成长/进化模拟 -> 战斗状态机 -> 资源与后端存储 -> 商店/道具 -> 存档同步 -> 动画与游戏性补点
```

## 3. 优先级最高的已知风险点

### P0-1：历史非等级进化声明仍在数据中，必须持续审计等级映射与展示一致性

当前运行时已经统一为等级触发进化，但 `MONSTERS` 数据里仍保留石头进化、交换进化、亲密度、学会某技能、招式使用、分支进化等历史声明。

排查目标：

- 确认所有历史分支都已映射到明确的等级阈值，且不会漏链、死链、循环或错链。
- 确认图鉴、成长弹窗、成长模拟脚本与现行等级规则一致，不再误导成“必须额外条件”。
- 保留原始数据声明用于审计，但不能让旧触发方式重新渗回主玩法链路。

### P0-2：多级升级时技能与进化事件可能受旧状态影响

`gainExpAndLevelUp` 在循环升级时保留的是升级前 `mon.moves`，并且每轮使用原始 `mon.baseId` 查基础形态。一次跨多级时可能影响：

- 新学技能去重。
- 多个技能连续学习的事件顺序。
- 进化后是否应该使用新形态 learnset。
- 进化后再升级是否仍按旧形态判定。

排查目标：

- 用所有宝可梦 Lv.1 到 Lv.100 模拟，找出跨多级升级时事件队列是否正确。
- 专测经验药水一次跨多个等级、战斗奖励跨多个等级、Lv.15 到 Lv.20 这类同时触发技能和进化的边界。
- 额外记录“升级后实例重算是否仍使用初始形态基准”，避免未来成长公式调整时重新引入双轨回归。

### P0-3：成长事件队列已接入云存档，但中断恢复仍需最终手测闭环

`pendingGrowthEvents` 已经进入云存档快照，但升级弹窗、忘技能弹窗、进化弹窗、刷新恢复这些界面级场景还需要最终人工回归确认。

排查目标：

- 测试升级弹窗中刷新、进化动画中刷新、忘技能选择前刷新。
- 确认读回后不会漏学技能、漏进化、重复学技能、重复进化。
- 验证 `game_saves` 读回后不会重复消费、漏消费或错序消费事件。

### P0-4：购买、奖励领取、道具使用存在跨后端和前端存档的原子性风险

典型风险：

- 金币已扣，但背包增加尚未成功保存。
- 老师奖励已被 `claim_teacher_rewards` 标记领取，但前端队伍或背包没保存成功。
- 经验药水已消耗，但升级/学技能/进化结果未保存完整。
- 捕捉成功后若队伍已满，待安置弹窗和新捕获宝可梦上下文必须跟随云存档一起恢复。

排查目标：

- 所有资源扣发类操作都要测 RPC 成功、RPC 失败、云存档失败、刷新恢复、重复点击。
- 对不可回滚的操作建立补偿策略或可重试确认机制。
- 明确记录“当前测试环境是否已经部署 `202605180003_teacher_reward_claim_handshake.sql` 与 `202605180004_atomic_resource_save.sql`”，不要把仓库已修复误写成线上已无风险。

### P0-5：产品规则与 README 可能不一致

`README.md` 中描述“战斗、捕获、地图探索不再直接获得经验或金币”，但当前 `grantBattleRewards` 会在战斗胜利后发经验和金币。

排查目标：

- 明确产品规则：战斗是否应该给经验和金币。
- 若战斗应该给奖励，更新 README 和教学说明。
- 若战斗不应该给奖励，调整 `grantBattleRewards` 或通过配置关闭。

### P1-6：战斗审计脚本已可运行，Vite WebSocket 噪声已清理

`npm run audit:battle` 已经可以作为固定审计命令运行，当前复验不再打印 `EPERM` WebSocket 监听噪声。

排查目标：

- 保持脚本持续可运行。
- 后续若脚本环境调整导致噪声回归，需要重新压掉，避免干扰阅读结果。

## 4. 阶段 0：审计保护与测试基线

目的：避免排查过程中破坏真实学生数据，并为每个问题留下可复现证据。

检查项：

- 建立专用测试学生账号和测试老师账号。
- 记录测试前 `users.gold`、`users.energy`、`users.max_energy`。
- 记录测试前 `game_saves.game_data`、`save_revision`、`last_saved`。
- 记录测试前背包、队伍、活跃宝可梦、地图位置、当前回合状态。
- 明确哪些测试允许扣金币、扣能量、消耗道具、清空或重建存档。

每个测试用例必须记录：

- 操作前前端状态。
- 操作前后端状态。
- 操作步骤。
- 操作后前端即时状态。
- 操作后 `users`、`gold_logs`、`energy_logs`、`teacher_rewards`、`game_saves` 状态。
- 刷新页面后读回状态。
- 双标签页或网络异常时的恢复状态。

验收标准：

- 不使用正式学生账号做破坏性测试。
- 每个 P0 风险都有可复现步骤或明确排除证据。
- 任何可能导致资源损失的测试，都能从后端日志定位到具体记录。

## 5. 阶段 1：全宝可梦、技能、进化静态数据审计

目的：先排除硬数据错误，避免运行时出现未知宝可梦、未知技能、未知进化目标、图片缺失等问题。

### 5.1 宝可梦基础数据

检查项：

- `id` 唯一。
- `dexNo` 或 `pokedexId` 存在，并与图片路径可对应。
- `name` 非空。
- `type`、`type2` 必须在 `TYPES` 中。
- `maxHp`、`maxMp`、`atk`、`def`、`spAtk`、`spDef`、`spd` 都为正数。
- `moves` 是数组，长度不超过 4。
- `moves` 中每个技能 key 都存在于 `MOVES`。
- 初始或兜底技能中至少有一个 `cost: 0`，避免 MP 用完后彻底无法行动。
- `sprite`、`backSprite`、`fallbackSprite` 能加载。

### 5.2 技能数据

检查项：

- 每个技能都有 `name`、`type`、`power`、`accuracy`、`category`、`cost`、`unlockLevel`。
- `category` 只能是 `physical`、`special`、`status`。
- `accuracy` 范围为 1 到 100。
- `power` 不小于 0。
- `cost` 不小于 0。
- `unlockLevel` 范围为 1 到 100。
- `status` 只使用战斗流程支持的状态：`sleep`、`poison`、`burn`、`paralysis`、`freeze`。
- `volatileStatus` 只使用战斗流程支持的状态：`flinch`、`confusion`。
- `effect` 只使用已实现效果：`heal`、`drain`。
- `requiresTargetStatus` 指向已支持的主状态。
- `statChange.stat` 只使用 `atk`、`def`、`spAtk`、`spDef`、`spd`、`accuracy`。
- `statChange.target` 只使用战斗执行器支持的 `attacker`、`defender`。
- `statusChance`、`volatileChance`、`statChange.chance` 在 1 到 100。
- `priority` 在可解释范围内，避免异常先制值。
- `charge` 为布尔值。
- `charge` 技能能被蓄力流程正确处理。
- 变化类技能不能是“有按钮、有耗蓝、但运行时无任何效果”的空操作。

### 5.3 学技能数据

检查项：

- `learnset` 中每个等级为 1 到 100。
- `learnset` 中每个技能存在于 `MOVES`。
- 同一等级多个学习事件是否被支持；当前结构 `{ [level]: moveKey }` 只天然支持一个技能，需要确认是否足够。
- `getBalancedMovesForLevel` 自动补技能是否会提前给出太强技能。
- 宝可梦原始阶段和进化阶段是否应共享技能池，还是应独立技能池。

### 5.4 进化数据

检查项：

- 每个 `evolvesTo.targetId` 存在。
- 每个 `alternateEvolutions.targetId` 存在。
- 等级进化 level 在 1 到 100。
- 进化链无循环。
- 进化链无断点。
- 非等级进化必须标注处理策略：实现、隐藏、暂未开放、改为等级进化。
- 分支进化必须明确选择方式：道具、时间、亲密度、界面选择、随机或暂不开放。

### 5.5 地图刷怪数据

检查项：

- `MAP_CONFIG` 每张地图 `wildPokemon.id` 都存在于 `MONSTERS`。
- `weight` 为正数。
- `minLevel <= maxLevel`。
- 地图推荐等级、野怪等级、能量消耗、捕捉难度相匹配。
- 地图中不会刷出当前阶段无法合理击败或无法捕捉的宝可梦。

### 5.6 道具和资源文件

检查项：

- `POKEBALLS`、`POTIONS`、`EXP_POTIONS`、`EVOLUTION_ITEMS` 中每个 item key 唯一。
- 每个道具有 `name`、`price`、对应效果参数和 `sprite`。
- 价格为正数。
- 精灵球捕捉倍率为正数。
- 回复药恢复量为正数。
- 经验药水经验量为正数。
- 进化道具至少要有可识别的 `itemKey`、价格和占位素材，并明确是否“可直接使用”还是“仅为后续规则预留”。
- 所有道具图片实际存在。

验收标准：

- 生成静态审计报告，列出所有错误、警告、待确认项。
- P0 数据错误必须修复后才能进入战斗和存档压力测试。

## 6. 阶段 2：升级、经验、学技能、忘技能、进化审计

目的：保证所有宝可梦从 Lv.1 到 Lv.100 的成长曲线、技能学习、进化结果可预测、可恢复、可保存。

### 6.1 等级与经验曲线

检查项：

- `getExpToNextLevelOfficial(level)` 在 Lv.1 到 Lv.99 均为正数。
- Lv.100 的 `expToNextLevel` 为 0。
- `currentExp` 不会出现负数。
- 升级后剩余经验正确结转。
- 一次获得大量经验可以连续升级到正确等级。
- Lv.100 使用经验药水不消耗道具。
- 经验药水、战斗奖励、老师奖励宝可梦等级都使用一致的等级边界。

测试场景：

- Lv.5 当前经验 0，获得不足升级经验。
- Lv.5 当前经验差 1 点升级，获得 1 点。
- Lv.5 当前经验差 1 点升级，获得 1000 点。
- Lv.99 获得大量经验到 Lv.100。
- Lv.100 使用小、中、大经验药水。

### 6.2 属性成长曲线

检查项：

- 每级 `maxHp`、`maxMp`、`atk`、`def`、`spAtk`、`spDef`、`spd` 随等级提升不下降。
- 进化后属性符合目标形态种族值。
- 升级时当前 HP/MP 的处理规则明确：全恢复、按比例、保持原值或其他。
- 进化时 HP 比例保持逻辑正确。
- 异常状态、临时能力等级、混乱/畏缩等战斗临时状态在进化后清理规则正确。

### 6.3 学技能与忘技能

检查项：

- 技能少于 4 个时自动学习。
- 技能等于 4 个时弹出选择。
- 选择遗忘第 1、2、3、4 个技能都能正确替换。
- 选择放弃学习不会消耗其他状态。
- 已经拥有的技能不会重复学习。
- 一次升级触发多个技能事件时，事件顺序稳定。
- 一次跨多级触发多个技能事件时，所有事件都保留。
- 弹窗中刷新页面后不会丢失学习事件。

### 6.4 进化事件

检查项：

- 达到进化等级时触发进化。
- 未达到进化等级时不触发。
- 一次跨过进化等级仍能触发。
- 进化目标形态正确。
- 进化后 `baseId` 更新为新形态。
- 进化后 `moves` 是否保留，规则与产品设计一致。
- 进化后是否学习目标形态技能，规则明确。
- 进化事件和学技能事件的顺序符合产品规则。
- 进化动画中刷新页面不会丢进化。

### 6.5 全量模拟脚本

计划新增：

```text
scripts/audit-growth-sim.mjs
```

脚本输出：

- 每只宝可梦 Lv.1 到 Lv.100 的属性表。
- 每只宝可梦每级应学技能。
- 每只宝可梦每级应触发进化。
- 跨等级升级事件队列模拟。
- 异常项：漏技能、重复技能、无可用技能、进化目标不存在、进化后 baseId 异常。

验收标准：

- 所有宝可梦 Lv.1 到 Lv.100 模拟无崩溃。
- 所有成长事件都有明确期望和实际结果。
- 刷新恢复不会丢失待处理成长事件。

## 7. 阶段 3：战斗流程审计

目的：保证战斗状态机稳定，HP、MP、状态、奖励、捕捉、失败、胜利流程都不会漏处理或重复处理。

### 7.1 战斗入口

检查项：

- 野外遇敌前先刷新后端能量。
- 能量不足不创建战斗。
- 能量扣除成功后才创建敌方队伍。
- RPC 失败不进入战斗。
- 没有可出战宝可梦时不能开始战斗或能自动切换到可出战宝可梦。
- 训练家战斗消耗正确能量。
- 训练家队伍数量和等级合理。

### 7.2 回合顺序

检查项：

- 技能优先级高的一方先动。
- 优先级相同，速度高的一方先动。
- 同速时随机先手。
- 麻痹导致速度减半后重新计算顺序。
- 畏缩只影响尚未行动的目标。
- 先手击倒目标后，目标不能继续行动。
- 回合解析中途失败不会卡死在 `resolving`。

### 7.3 MP 和技能消耗

检查项：

- MP 不足时玩家技能按钮不可用或点击后只提示，不扣资源。
- 敌方 MP 不足时能跳过行动或选择可用技能。
- `cost: 0` 技能可无限使用。
- 普通技能按 `cost` 扣除。
- 蓄力技能第一回合和释放回合扣除规则一致。
- 蓄力中被击倒、切换、捕捉、逃跑后状态清理。
- MP 不会变成负数。

### 7.4 伤害公式

检查项：

- 物理技能使用 `atk` 对 `def`。
- 特殊技能使用 `spAtk` 对 `spDef`。
- 属性克制倍率正确。
- 双属性倍率正确相乘。
- 免疫时伤害为 0。
- STAB 同属性加成正确。
- 随机伤害范围在 85 到 100。
- 最低伤害保护生效。
- 同级伤害上限生效。
- 灼伤降低物攻生效。
- 能力等级变化影响伤害。

### 7.5 状态与效果

检查项：

- 睡眠持续回合正确。
- 冰冻 20% 解冻逻辑正确。
- 麻痹 25% 不能行动逻辑正确。
- 中毒每回合扣最大 HP 的 1/8。
- 灼伤每回合扣最大 HP 的 1/16。
- 混乱持续回合和自伤概率正确。
- 畏缩只持续一次行动检查。
- 属性免疫状态正确：毒系免疫中毒、火系免疫灼伤、电系免疫麻痹、冰系免疫冰冻。
- 已有主状态时不能叠加新的主状态。
- `drain` 吸血和 `heal` 回复不会超过最大 HP。
- `requiresTargetStatus` 不满足时不会造成不该有的效果。

### 7.6 濒死、胜利、失败

检查项：

- 敌方倒下后发放奖励一次。
- 训练家多只宝可梦时，击倒每只都能进入下一只。
- 击败最后一只后进入胜利过场。
- 玩家宝可梦倒下后，有后备时进入换人界面。
- 玩家全队倒下后进入失败流程。
- 胜利后临时战斗状态清理。
- 训练家战斗胜利后是否全队恢复，规则明确。
- 战斗结束返回地图时，`participatedMonIds`、捕捉动画状态、战斗种类等临时字段必须一起清理。

### 7.7 捕捉与逃跑

检查项：

- 精灵球数量不足不能使用。
- 使用精灵球立即消耗，成功和失败都消耗。
- 捕捉率受 HP、MP、球倍率、等级差影响。
- 捕捉成功后加入队伍，重置 HP/MP/经验。
- 捕捉失败后敌方行动。
- 训练家宝可梦明确禁止捕捉，且前端必须在消耗精灵球前拦截。
- 训练家对战明确禁止逃跑，UI 和逻辑都要双重拦截。
- 逃跑成功返回地图并清理战斗状态。
- 逃跑失败后敌方行动。
- 当前执行备注：
  - 精灵球开场已改为先提交“扣球 + 进入捕捉中 + 写入 `captureSequenceData`”的云快照，再播放动画。
  - 捕捉结算已开始改为基于最新云端快照提交成功/失败结果。
  - `encounterCooldownSteps` 已进入云快照 schema；最终手测重点改为确认“捕捉成功、逃跑成功、换图后回到地图”的安全步数在刷新后不会丢失。

验收标准：

- 所有战斗结束路径都能回到稳定视图。
- HP、MP、状态、奖励不会重复扣发。
- 没有卡在 `capture`、`enemy`、`resolving`、`battlePhase` 的状态。

## 8. 阶段 4：金币、能量、经验、血量、技能值变化审计

目的：保证关键资源变化准确、后端日志完整、刷新后读回一致。

### 8.1 金币

检查项：

- 战斗金币奖励是否符合最终产品规则。
- 商店购买扣金币成功后 `users.gold` 更新。
- 金币不足时后端拒绝，不增加背包。
- 连续点击购买不会扣成负数。
- 双标签页同时购买不会出现余额冲突。
- `gold_logs` 每次变动都有记录。
- 前端显示金币以 `users.gold` 后端值为准。

### 8.2 能量

检查项：

- 野外战斗能量消耗正确。
- 训练家战斗能量消耗正确。
- 能量不足时不能开始战斗。
- 后端 `adjust_energy` 不允许学生端正向增加能量。
- 老师端 `grant_energy` 可恢复或调整上限。
- 能量不会低于 0。
- 能量不会超过合理上限，若超过有老师端警告。
- `energy_logs` 每次变动都有记录。

### 8.3 经验

检查项：

- 战斗经验是否符合最终产品规则。
- 经验药水增加经验准确。
- 参与战斗宝可梦平分经验。
- 多只敌人连续战的经验不会漏发或重复发。
- 经验变化后立刻触发升级流程。
- 升级结果能保存并读回。

### 8.4 HP 与 MP

检查项：

- 战斗扣 HP 后前端显示、队伍状态、云存档一致。
- 药水回复 HP 后保存并读回一致。
- 精灵之泉、浆果、训练家胜利恢复等回复点规则一致。
- 技能扣 MP 后保存并读回一致。
- 战斗结束后临时状态清理，但持久 HP/MP 规则符合设计。

验收标准：

- 所有资源变化后端可追踪。
- 刷新后不会回退到旧金币、旧能量、旧背包、旧队伍。
- 并发或网络慢时不会负数、重复扣、重复发。

## 9. 阶段 5：商店、背包、道具审计

目的：保证购买、使用、消耗、生效、保存形成闭环。

### 9.1 商店购买

链路：

```text
点击购买 -> 刷新金币 -> 校验余额 -> adjust_gold 扣金币 -> addInventoryItem 增加背包 -> 触发关键云保存
```

检查项：

- 商品类型无效时拒绝。
- 数量无效时拒绝。
- 金币不足时拒绝。
- 扣金币失败时不增加背包。
- 扣金币成功但保存失败时有补偿或重试策略。
- 重复点击不会重复购买到异常数量。

### 9.2 回复药

检查项：

- 没有药时不能使用。
- 满血时不消耗。
- 受伤时回复正确数值。
- 回复后不超过最大 HP。
- 背包数量扣除正确。
- 战斗中和地图中使用规则一致。
- 濒死宝可梦是否允许用药复活，规则明确。

### 9.3 经验药水

检查项：

- 没有经验药水时不能使用。
- 满级时不消耗。
- 有效使用后经验增加正确。
- 跨多级时所有升级、学技能、进化事件完整。
- 当前为“本地状态更新 + 强制云存档”模式，尚未接入独立原子 RPC；若云存档失败，应由全局同步阻断器拦截继续游玩。
- 弹窗中刷新不会导致药水已扣但成长事件丢失。

### 9.4 精灵球

检查项：

- 只能在玩家回合使用。
- 没有球时不能使用。
- 训练家对战中禁止使用，且必须在扣球前拦截。
- 使用后立即扣数量。
- 捕捉成功加入队伍。
- 捕捉失败进入敌方行动。
- 成功或失败后都能保存并读回。
- 捕捉动画中刷新不会重复加队伍或返还球。

### 9.5 老师奖励

链路：

```text
老师端发放 -> teacher_rewards 写入 -> 学生端 begin_teacher_reward_claim 预留批次 -> 基于最新云快照提交奖励结果 -> confirm_teacher_reward_claim 确认领取
```

检查项：

- 道具奖励类型和 key 必须有效。
- 若后端仍返回历史 `evolutionItem`，前端必须明确标记“已停用”并拒绝注入活跃背包。
- 宝可梦奖励 ID 必须存在。
- 宝可梦奖励等级在 1 到 100。
- 领取后前端背包或队伍增加。
- 领取后云存档成功。
- 奖励应用必须基于最新云快照构造，不能先改本地再等 autosave。
- 若领取后云存档失败，不应永久丢奖励。
- 多个奖励一次领取顺序稳定。
- 已有待安置宝可梦、仓库已满时，奖励宝可梦必须明确阻断并给出可恢复提示。

验收标准：

- 每种道具都有购买、使用、保存、刷新读回用例。
- 老师奖励不会因前端保存失败而丢失。

### 9.6 地图交互奖励

链路：

```text
地图交互触发 -> handleCollect 决定是否成功消费 -> 成功时一起提交奖励结果与 mapGrid 清格 -> 刷新后读回
```

检查项：

- 地图道具奖励必须在奖励真正写入背包后才清格。
- 回血点必须在队伍恢复结果成功保存后才清格。
- 果实必须在恢复结果成功保存后才清格。
- 商人奖励必须在物品真正写入背包后才清格。
- 训练家挑战只有在成功进入战斗后才算消费互动，能量不足或开战失败时不能从地图消失。
- 云端冲突、离线、同步失败时，地图交互不能先清格再报错。

验收标准：

- 地图交互奖励不会出现“奖励没到账，但地图点位没了”。
- 训练家不会出现“没打成却消失”的情况。

## 10. 阶段 6：云存档与“回退一秒”专项

目的：专门验证旧请求、旧标签页、慢网络、离线恢复不会覆盖新进度。

### 10.1 云存档写入

检查项：

- 自动保存防抖正常触发。
- 关键操作 `requestCriticalCloudSave` 后能强制保存。
- 页面隐藏时强制保存。
- 固定间隔保存兜底。
- 保存中产生新变化时能排队继续保存。
- `lastSavedSnapshotRef` 不会误判已保存。
- `save_revision` 单调递增。

### 10.2 云存档读取

检查项：

- 登录后必须从云端读取。
- 读取失败不能进入可操作游戏。
- 离线时阻断游戏。
- 金币、能量从 `users` 读取。
- 游戏进度从 `game_saves` 读取。
- 历史 `evolutionItem` 不能在读档时重新注入活跃背包。
- 地图内容版本变更时位置重置逻辑符合预期。
- 战斗状态读回时不会进入无敌方的战斗。

### 10.3 旧进度覆盖防护

测试场景：

- 打开两个标签页 A 和 B。
- A 购买道具并保存到 revision 10。
- B 停留在 revision 9 后尝试保存。
- 后端必须拒绝 B 的旧版本覆盖。
- 前端必须提示“旧进度被阻止覆盖”，并要求重新读取云端。
- 冲突后顶部云按钮与 `CloudSyncBlocker` 按钮必须切换成“重新读取云端进度”，不能继续走“保存云端”。
- 冲突态下自动保存、防抖保存、定时保存、页面隐藏保存必须暂停，直到成功重新读取云端。

### 10.4 中断恢复场景

必须测试：

- 战斗中刷新。
- 捕捉动画中刷新。
- 捕捉成功后未返回地图就刷新。
- 升级弹窗中刷新。
- 忘技能选择中刷新。
- 进化动画中刷新。
- 商店扣金币后刷新。
- 经验药水使用后刷新。
- 老师奖励领取后刷新。
- 地图道具 / 回血点 / 果实 / 商人奖励触发后刷新。
- 训练家能量不足时触发交互。
- 离线后继续点击操作。
- 网络恢复后重试同步。

验收标准：

- 刷新后不会回退到前一秒旧状态。
- 旧标签页不能覆盖新标签页。
- 保存失败时游戏会阻断或明确提示，不让玩家继续制造更复杂的冲突状态。
- revision 冲突后的恢复动作只能是“重读云端”，不能把本地旧快照再次推送到后端。

## 13. 优先级定义

| 优先级 | 定义 | 示例 |
| --- | --- | --- |
| P0 | 会导致进度回退、资源丢失、重复扣发、无法继续游玩、严重数据错误 | 旧存档覆盖新存档、金币已扣但物品丢失、升级事件丢失 |
| P1 | 会明显影响核心玩法正确性，但通常有恢复路径 | 进化方式未实现、战斗奖励规则不一致、部分状态异常 |
| P2 | 影响平衡、体验或可维护性，但不直接破坏数据 | 技能过强、动画反馈不足、文档与实现不一致 |
| P3 | 品质增强或后续扩展 | 更丰富的动画、音效、战斗表现、运营工具 |
