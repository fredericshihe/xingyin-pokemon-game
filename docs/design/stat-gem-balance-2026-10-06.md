# 单项属性宝石

| 道具 | 金币 | 单次永久基础提升 | 80级面板提升 |
| --- | ---: | ---: | ---: |
| HP之石 | 20000 | HP +5 | +8 |
| 攻击之石 | 20000 | 攻击 +3 | +4～5 |
| 防御之石 | 20000 | 防御 +3 | +4～5 |
| 特攻之石 | 20000 | 特攻 +3 | +4～5 |
| 特防之石 | 20000 | 特防 +3 | +4～5 |
| 速度之石 | 25000 | 速度 +2 | +3～4 |

每只宝可梦的新规则使用额度为10颗，同一属性最多4颗。六种单属性之石共用额度，商店和探索获得的同类道具使用相同规则。神奇糖果不出售；探索奖励的全属性+5保持原规则，不消耗单属性宝石额度。

价格和面板增量来自当前运行公式。六只80级对手的联赛铜/银/金奖为4104/5130/6156金币；20000金币对应不喝药5/4/4场胜利，每场使用两瓶1000金币超级伤药则为10/7/5场。这是经济与属性计算，不能推断调整后的实战胜率。

使用次数保存在每只宝可梦的`statGemUses`，按`maxHp/atk/def/spAtk/spDef/spd`计数。升级、进化、队伍和仓库移动、JSON读档均保留该字段。历史`statBoosts`原样保留；不同来源的旧加成无法可靠反推使用次数，所以旧存档从0次新额度起算。

属性加成、库存扣除和次数增加在同一云存档事务完成；达到上限或提交失败不消耗道具。后端验证单项4颗、总共10颗、计数不回退、属性增量、库存消耗和战斗外使用。`statGemTrainingVersion=1`标记采用新规则，后端保留该版本；上线迁移时尚未采用新规则的旧客户端仍可保存，避免前后端发布之间阻断玩家。

验证：`npm run audit:stat-gems`检查价格、全部物种单项面板、历史加成、叠加上限、读档、升级、仓库和商店渲染。`scripts/audit-stat-gem-training.sql`在回滚事务中使用虚构数据验证数据库函数与触发器，不修改玩家存档。
